# xueqiu-monitor v0.9 需求 — 轮换生命周期治理（Rotation Lifecycle Governance）

> 状态：需求草案，待用户决策后实施
> 日期：2026-09-12
> 前置：v0.8.6 (6c66046) 股票池 30→41 轮换已提交；9/12 复检确认代码/调度层干净

## 1. 定位与基线

**v0.8 基线**：pipeline 运行健康（9/9–9/11 日报 41 只正常出，CSV 763K→1.4M），git 工作区干净。但 9/12 复检发现轮换这个动作本身没有基础设施——本次轮换是用户在 Hermes 之外手工改 7 个 config JSON，改动游离 3 天未提交，事后验证链（JSON 合法性 / report 池=爬取并集 / cron 分组对应）全部靠人工重跑。

**v0.9 定位**：给「股票池轮换」补齐生命周期设施——**一个台账、一个工具、两条规范、三处死物清理**。让下一次轮换从「手工编辑 + 事后人工验证」变成「一条命令 + 全自动校验 + 台账留痕」。

## 2. 核心主题

### T1 轮换台账 `pool_history`（P0）

**问题**：为什么/何时出池无任何记录。9 只出池的理由（14d 日均帖量）只活在 commit message 里，无法程序化复盘。

**方案**：monitor.db 新增台账表：

```sql
CREATE TABLE IF NOT EXISTS pool_history (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    stock_code      TEXT NOT NULL,
    action          TEXT NOT NULL CHECK(action IN ('add','remove')),
    effective_date  TEXT NOT NULL,          -- YYYY-MM-DD
    reason          TEXT,                   -- 如 '低声量出池: 14d日均4.6帖'
    avg_daily_posts REAL,                   -- 轮换时声量快照，供复盘
    config_version  TEXT                    -- 如 'v0.8.6'
);
```

**回填**：从 git 历史回填两次轮换——`6c66046`（v0.8.6：9 remove + 20 add，reason 含 14d 日均帖量，全在 commit message 里）和 `118d41a`（v0.8.5 Plan C）。一次性脚本 `scripts/backfill_pool_history.py`，幂等（按 stock_code+effective_date 去重）。

**数据现状（9/12 实测）**：DB 累计 77 个 symbol vs 现池 41；池外 36（5 指数 + 31 个历史退场股票，含 ASML/TAL/SPOT——已由 morning-brief earnings 模块接管，ASML 在 earnings_calendar 有活跃记录）。

### T2 轮换工具 `scripts/rotate_pool.py`（P0）

**问题**：config 手工编辑无校验门。9/12 早晨人工跑的验证链（7 个 JSON 解析、report 池=爬取并集、分组无重复、cron 覆盖）本质上是这个工具的规格书。

**方案**：单一入口，两个模式：

```bash
# 体检模式：对当前 repo 跑全量校验，全绿退出 0
python3 scripts/rotate_pool.py --check

# 轮换模式：dry-run 默认，验证通过才落盘
python3 scripts/rotate_pool.py --plan rotation.json [--apply]
```

`--check` 校验项（全部来自 9/12 人工验证链）：
1. 6 个 config JSON 可解析
2. G0–G5 whitelist 并集 == `config.report.json` 的 `report.stocks`（当前 41=41）
3. 组间无重复 symbol
4. 每组非空、分组数与 cron job（xueqiu-pipeline-g1..g5 + 主 pipeline）一一对应
5. 41 池 ⊆ morning-brief DB active 集（真实爬取源，当前 41/41 覆盖）
6. `pool_history` 台账与当前 config 状态自洽（最后动作叠加 = 现池）

`--plan` 模式：解析 rotation.json（add/remove/分组调整 + reason）→ 跑同款校验 → 写台账 → 生成 commit message（含声量快照）→ 提示 git 操作。**不自动 commit**（保留人工门）。

### T4 source of truth 收敛（P1）

**问题（隐性依赖）**：爬取真实加载链是 morning-brief DB（69 active）> config whitelist fallback；`data/watchlist.json`（74 只，每日 12:00 从 longbridge 同步）第三层。三层漂移目前无害纯粹靠运气（41 池恰被 morning-brief 覆盖）。

**方案**：
1. 明文声明（README + skill）：**morning-brief DB 为爬取唯一真源，config.g*.json whitelist 是分组切片**，watchlist.json 仅作 longbridge 侧同步缓存
2. `xueqiu-sync-watchlist` 每日 job 追加一步一致性校验：41 池 ⊄ morning-brief active 时发飞书告警（当前轮换工具的 --check 第 5 项即此逻辑的轮换时版本，此处补运行时版本）

### T5 轮换质量复盘（P2）

出池股票 14d 后声量回看（当时判「低声量」是否误杀）→ 数据已在 `sentiment_stats`（出池股历史行保留），台账 `avg_daily_posts` 提供基线。v0.9 只留台账字段，复盘报告脚本 v1.0 再做。
