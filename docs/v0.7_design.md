## 1. v0.7 主题：从"稳定运行"到"信息增量"

v0.6 解决了稳定性（时间解析、分组调度、日报形态）。v0.7 聚焦三件事：
1. **告警有增量**（公告不再全静默）
2. **数据有新鲜度保障**（事故自愈而非人工发现）
3. **口径统一与减法**（衍生脚本对齐主路径，死代码清除）

## 2. 需求项

### F0. 立即修复包（N1-N3，半小时）— P0
- db.py:108 `log`→`logger`（一行）
- health_check.py 加 `from __future__ import annotations`（一行）
- requirements.txt 补 `jieba>=0.42`

### F1. 公告智能分级（N4）— P0
**问题**：所有公告一律 P2 静默。13G/13D（大额持仓变动）、业绩、并购与"月度 Routine 申报"同等对待。
**方案**：两段式分级
- 规则层（快，确定性）：公告类型映射表。13G/13D/业绩(预告|快报|年报|中报)/并购/回购/停复牌/监管处罚/配售融资 → P1；Routine（Rules 13a-16、Sections 13 or 15(d)、Accession 类周期申报、"其他"）→ P2
- LLM 层（可选，默认关）：对规则层判 P1 的公告标题做二次确认，过滤标题党
**公告深链**：标题正则提取 Accession Number（`000\d{2,6}-\d{2}-\d{6}`）构造 SEC EDGAR Archives 深链；HK 股 stockn.xueqiu.com PDF 已直达，保持
**验收**：CBRS 类 13G 触发 P1 汇总推送；Routine 月报不推；推送卡片链接直达详情页

### F2. 数据新鲜度哨兵（N5）— P0
**方案**：health_check 增加三项语义检查
1. last_crawl_time 新鲜度：meta 表全部股票距今 > 48h → FAIL
2. 帖子时间解析失败率：最近快照 time 字段解析失败率 > 30% → FAIL（8/8 事故当天即触发）
3. 快照内旧帖堆积：最新快照 >50% 帖子发布早于 7 天前 → WARN
FAIL 时经现有 13:30 cron + lark-card 推告警卡片。
**验收**：注入模拟坏数据触发 FAIL；正常数据不误报

### F3. 口径统一与脚本减法（N6/N7）— P1
- 删除 daily_sentiment_report.py（孤儿脚本，423 行，输出停更 5/31）——其"市场温度计"若仍想要，功能并入 report_generator 主路径（带时间过滤）
- 抽公共函数 `filter_posts_by_recency(posts, now, max_age_days)`；export_csv.py 复用（知识库场景放宽到 7 天）并修正 docstring
- 验收：CSV 不再含 >7 天旧帖

### F4. 热词治理 — P1
- cli.py:285 存储路径复用 detector `_CN_STOPWORDS` + `_is_short_token`（告警与存储口径统一）
- hot_word_dict 一次性清洗 migration（幂等删泛词行；hot_word_event 历史保留，连续天数口径不变）
- 验收：hot_word_dict top30 无泛词

### F5. 反馈闭环去留决策 — 需用户拍板
**选项 A（推荐）**：删死代码。feedback.py + content_weight/user_preference 表 + decay 逻辑全链路移除（含幂等 migration：PRAGMA table_info 检查后 DROP），系统定位收敛为"单向监控+日报"；需求文档"有效推送率"指标同步移除。

**依据**：3 个月 0 反馈数据，纯推送形态下用户无反馈意愿；先删后立优于拖着。
